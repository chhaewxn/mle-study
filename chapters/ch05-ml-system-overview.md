## CHAPTER 5. 피처 엔지니어링

> 피처 엔지니어링은 모델이 쓸데없는 정보에 속지 않고, 중요한 신호만 잘 보게 만드는 작업. 꼼꼼함이 생명 !
> 

### 5.1 학습된 피처 vs 엔지니어링된 피처 

- **딥러닝을 하면, 피처 엔지니어링이 필요가 없을까?**
   - 전반적으로는 가능하나, **프로덕션용 ML 모델은 대부분 딥러닝이 아님**
   - 따라서, **피처 엔지니어링은 여전히 중요함**

- **(고전 NLP) 스팸 여부 분류 모델링을 위한 피처 엔지니어링**
   - Lemmatization(표제어 추출)
   - Expanding Contraction(줄임말 확장)   
   - Punctuation(구두점) 제거
   - Lowercasing(소문자화)
   - n-gram 분할

- **n-gram이란?**
   - 주어진 텍스트 샘플 내 항목 n개의 연속 시퀀스
   - 항목: 음소(phoneme), 음절(syllable), 문자, 단어

- **딥러닝 기반 NLP 모델에서는**
   - (1) raw text를 tokenization(단어로 분할)
   - (2) 단어들로 어휘를 만들고
   - (3) 이를 사용해 각 단어를 one-hot vector로 변환

### 5.2 피처 엔지니어링 기법 

#### 5.2.1 결측값 처리 

- **결측의 3가지 유형**

   1. **비무작위 결측(MNAR, Missing not at random)**
      - 결측값이 발생한 이유가 **target 값**에 있는 경우
      - 예: 소득을 신고하지 않은 응답자의 경우, 소득이 높은 경향
   
   2. **무작위 결측(MAR, Missing at random)**
      - 결측값이 발생한 이유가 **target 값이 아닌 feature 값에** 있는 경우
      - 예: 성별이 'A'인 응답자가, 성별이 'B'인 응답자보다 연령 값에 응답을 안 하는 경향
   
   3. **완전 무작위 결측(MCAR, Missing completely at random)**
      - 결측값에 패턴이 없는 경우 (완전 무작위)
      - 이러한 경우는 매우 드묾

- **결측치 처리 기법**

   1. **결측값 삭제 (Deletion)**
      - **열 삭제**: 특정 피처의 상당 부분이 누락된 경우 제거
      - **행 삭제**: 유용한 경우는 결측값이 완전 무작위 & 결측 샘플 비중이 적을 때
   
   2. **결측값 대치 (Imputation)**
      - 해당 피처의 집계값으로 imputation 하는 경우 많음
        - 예: 평균, 중앙값, 최빈값
      - **주의**: Test set의 값을 포함하여 imputation 하는 경우, **DATA LEAKAGE 발생**
      - Imputation할 때에, 해당 피처에서 실제로 존재하는 값을 함부로 넣는 것이 위험할 수 있음
        - 예: 연령 결측값을 0으로 채우는 경우, ML 모델 파이프라인에서 에러 없이 잘 돌아가는 것처럼 보일 수 있음

#### 5.2.2 스케일링 

- **Feature Scaling(피처 스케일링)**

   - 적은 노력 대비 모델 성능 향상을 이끌어낼 수 있는 가성비 좋은 전처리
   - **Logistic Regression에서 스케일링을 하지 않으면, 성능 저하가 심각함**

- **대표적인 2가지 스케일링**

   1. **[0, 1] 범위 스케일링**
   
   $$x' = \frac{x - \min(x)}{\max(x) - \min(x)}$$
   
   2. **[a, b] 범위 스케일링**
   
   $$x' = a + \frac{(x - \min(x))(b - a)}{\max(x) - \min(x)}$$
   
   - 여기서 a=-1, b=1인 경우가 많이 쓰임
   - 경험상 [-1, 1]이 더 잘 동작한다고 함 (저자 피셜)
   - **임의의 범위로 스케일링하는 것은, 변수에 대해 아무런 분포 가정을 하지 않을 때에도 효과적**

- **Standardization(표준화)**

   - 피처가 Normal distribution을 따른다고 생각될 때, 평균이 0이고 분산이 1이 되도록 해주는 전처리 기법
   
   $$x' = \frac{x - \bar{x}}{\sigma}$$

- **스케일링 방법 선택 가이드**
   1. **이상치가 적고 분포가 비교적 고르다면?** → `StandardScaler` 혹은 `MinMaxScaler`
   2. **이상치가 많고 분포가 불안정하다면?** → `RobustScaler`
   3. **데이터가 심하게 왜곡(Skewed)되어 모델 성능이 안 나온다면?** → `Log Transform`이나 `PowerTransformer`로 정규화를 먼저 시도한 후 스케일링

- **Log Transformation(로그 변환)**

   - Box-Cox Transformation도 유사한 목적으로 사용됨

- **스케일링에 대한 주의 사항**
   - **Warning 1**: Data Leakage의 원인이 되는 경우가 많음
   - **Warning 2**: 전역 통계치가 필요한 경우가 많음
     - 단점: 이로 인해, 훈련 데이터에 새로운 행이 추가되면 모델을 계속 재훈련해줘야 함

#### 5.2.3 이산화 

> 실제로 이산화가 도움이 되는 경우는 거의 없음 !

- **이산화와 동의어**
   - 이산화(binarization) = 양자화(quantization) = 비닝(binning)

- **이산화의 단점**
   - **범주 경계를 설정함으로써, 불연속성을 발생시킴**
     - 예: $100,000은 $35,000와 동일하게 처리되지만, 실제로 $35,000과 더 가까운 $34,999는 완전히 다른 값으로 처리됨
   - 시간이 흐르면서 데이터 분포가 바뀔 때마다, 사람이 유지보수하기도 어려움

#### 5.2.4 범주형 피처 인코딩 

- **정적 범주 (Static Categories)**
   - 연령 버킷, 소득 버킷 등
   - 범주 개수의 사전 파악 가능
   - 단순한 번호 부여로 처리 가능

- **동적 범주 (Dynamic Categories)**
   - 제품 브랜드, 사용자 계정, 웹사이트 도메인, IP 주소 등
   - 시간이 지남에 따라 새로운 범주가 지속적으로 생성됨

---

- **해싱 트릭 (Hashing Trick)**: 마이크로소프트의 **Vowpal Wabbit** 패키지를 통해 대중화된 기법
   - 해시 함수를 사용하여 각 범주 문자열을 고정된 해시 값으로 변환
   - 변환된 해시 값을 해당 범주의 인덱스로 직접 사용

   1. **고정된 피처 개수 유지**
      - 전체 범주 개수를 미리 파악할 필요 없음
      - 사전에 해시 공간(인덱스 범위)을 지정하여 피처 벡터의 차원을 고정
      - 예시: 18비트 해시 공간 설정 시 $2^{18} = 262,144$개의 고정된 인덱스 확보
      - 모든 범주를 0~262,143 사이의 값으로 매핑
      - 모델이 본 적 없는 신규 범주도 별도 처리 없이 즉시 인덱싱 가능
   
   2. **유연한 신규 범주 처리**
      - 별도의 사전(Vocabulary) 관리나 UNKNOWN 범주 없이 신규 데이터 처리 가능

- **해시 충돌 (Hash Collision)**
   - 문제: 서로 다른 두 범주가 우연히 동일한 해시 인덱스를 배정받는 현상
   - 긍정적 측면
     - 충돌은 무작위로 발생하므로, 신규 브랜드가 반드시 '비인기 브랜드'와 묶이는 편향이 없음
     - 기존의 인기 브랜드와 인덱스를 공유하게 될 가능성도 존재 (모델 성능에 큰 해를 끼치지 않음)

- **충돌 최소화 전략**
   1. **충분히 큰 해시 공간 확보**: 메모리가 허용하는 한 해시 공간을 늘려 충돌 확률 감소 유도
   2. **특수 해시 함수 활용**:
      - **지역 민감 해싱(LSH)**: 유사한 이름의 범주(예: 오타)가 서로 가까운 값으로 해시되도록 하여 정보를 보존

- **학계 vs 업계의 시각**
   - 학계: 이론적 정합성이 부족한 '트릭'으로 간주하여 교육 과정에서 제외되는 경향
   - 업계: 높은 효율성과 검증된 효과로 인해 널리 채택됨 (Vowpal Wabbit, Scikit-learn, TensorFlow 등에서 지원)
   - **최적 활용**: 스트리밍 데이터와 같이 데이터가 계속 유입되는 **연속 학습(Continuous Learning)** 환경

#### 5.2.5 피처 교차 

- **피처 교차(Feature Crossing)** 는 둘 이상의 피처를 결합하여 새로운 합성 피처를 생성하는 기법
- **목적**: 단순한 피처의 나열로는 표현할 수 없는 **비선형 관계의 모델링**

- **선형 모델에서의 필수 요소**
   - 한계: 선형 회귀나 로지스틱 회귀는 각 피처의 독립적인 영향력만 학습 가능 (XOR 문제 해결 불가)
   - 해결: 피처 교차를 통해 변수 간의 상호작용 정보를 명시적으로 제공해야 함

- **신경망 모델에서의 활용**
   - 신경망은 레이어를 통해 자동으로 비선형성을 학습하지만, 명시적 피처 교차가 학습 속도와 성능을 향상시킬 수 있음
   - 사례: **DeepFM**, **xDeepFM** 등 추천 시스템 모델에서 피처 간 상호작용을 명시적으로 모델링하여 성능 극대화

- **피처 교차의 주의사항**

   1. **피처 공간 폭발 (Feature Space Explosion)**
      - 상황: 값의 종류가 100개인 피처 A와 100개인 피처 B를 교차
      - 결과: $100 \times 100 = 10,000$개의 희소(Sparse)한 피처 생성
      - 위험: 모델이 학습해야 할 파라미터 수의 급격한 증가
   
   2. **과적합(Overfitting) 위험**
      - 피처가 너무 구체화(Specific)되면 훈련 데이터의 노이즈까지 암기할 가능성 증대
      - 대응: 적절한 정규화(Regularization)와 충분한 훈련 데이터 확보 필수

#### 5.2.6 이산 및 연속 위치 임베딩 

- **위치 임베딩의 등장 배경**
   
   - 출처: "Attention Is All You Need" (Transformer 모델의 시초)
   - 의의: 딥러닝 분야, 특히 컴퓨터 비전과 NLP의 표준 기술로 정착

- **임베딩의 정의와 확장**

   > 임베딩(Embedding): 데이터를 기계가 이해할 수 있는 고정된 크기의 벡터로 변환한 것
   
   - **임베딩 공간(Embedding Space)**: 동일한 규칙으로 생성된 벡터들이 존재하는 기하학적 공간 (유사한 데이터는 가까이 위치)
   
   **종류의 다양화**
   - 전통적: 단어 임베딩
   - 현대적: 제품(커머스), 이미지(핀터레스트), 그래프(SNS), 쿼리(검색), 사용자(추천) 임베딩 등
   - 최신 트렌드: 다양한 형태의 데이터를 아우르는 **멀티모달 범용 임베딩** 연구

- **RNN vs Transformer 구조적 차이**
   - **순환 신경망(RNN)**: 데이터를 앞에서부터 순서대로 하나씩 처리하므로 '순서 정보'가 자연스럽게 반영됨
   - **트랜스포머(Transformer)**: 문장 전체를 한 번에 병렬로 처리함. 이로 인해 "아이가 개를 물다"와 "개가 아이를 물다"를 구별하기 위해 **단어의 위치 정보를 인위적으로 주입해야 함**

- **위치 임베딩 구현 방법**

   **방법 1: 학습 가능한 위치 임베딩 (Learnable Positional Embedding)**
   
   - 개념: 단어 임베딩처럼 위치 정보 자체도 학습을 통해 최적의 벡터값을 찾아내는 방식
   - 구현 원리:
     1. 단어 임베딩: '사과'라는 단어 → 벡터 A
     2. 위치 임베딩: '첫 번째 위치' → 벡터 B
     3. 최종 입력: 벡터 A + 벡터 B (단어의 의미와 위치 정보를 합산)
   - 특징:
     - BERT 모델(Hugging Face 구현체 등)에서 주로 사용
     - 데이터에 맞춰 위치 표현 방식이 유동적으로 최적화됨
   
   **방법 2: 고정 위치 임베딩 (Fixed Positional Embedding)**
   
   - 개념: 학습되지 않는 고정된 사인(sin), 코사인(cos) 함수를 사용하여 위치별 고유 벡터를 생성
   - 트랜스포머의 방식:
     - 짝수 차원에는 사인 함수, 홀수 차원에는 코사인 함수를 적용
     - 장점: 학습 데이터보다 더 긴 문장이 들어와도 수학적 규칙에 의해 위치 정보 추론 가능
   - 수식적 정의:
   
   $$PE_{(pos, 2i)} = \sin\left(\frac{pos}{10000^{2i/d}}\right)$$
   
   $$PE_{(pos, 2i+1)} = \cos\left(\frac{pos}{10000^{2i/d}}\right)$$
   
   (여기서 $pos$는 위치, $i$는 차원 인덱스)

### 5.3 데이터 누수 

- **데이터 누수의 정의**

   - 모델이 실제 예측 시점에는 절대 **알 수 없는 정보까지 학습에 사용**해 버리는 현상
   - 학습/검증 성능은 높고, 실제 성능은 급격히 하락함

#### 5.3.1 일반적인 원인 
   
   **1) 시간 정보를 무작위로 분할한 경우**
   
   - 대부분 데이터는 시간 상관관계 가지는데, 무작위 분할 시 미래 정보가 훈련 데이터에 포함됨
   - 예: 7일치 데이터가 있을 때 무작위로 1, 3, 7을 뽑아 쓰면 이후에 1-6일치로 7일 값 예측 시 데이터 누수 이미 발생
   - 주가, 클릭 예측 등은 **반드시 시간 기준 분할** 필요
   - 미래 정보가 훈련 과정에 유출되지 않도록 과거 데이터는 훈련을, 미래 데이터는 검증/테스트 용도로 사용
   
   **2) 분할 전 스케일링 / 결측값 처리**
   
   - 스케일링에 사용되는 평균, 분산은 전역 통계치인데 분할 전에 이를 계산하면 **테스트 정보가 훈련에 누출됨**
   - 테스트 분할에 대한 정보를 실수로 모델이 얻게 되버림 → 해당 데이터에 대해서만 예측 잘 나옴
   - 따라서 **항상 스케일링 전에 데이터 분할 + 훈련 분할치의 통계를 사용해서 모든 분할을 스케일링** 해야 함
   
   **3) 데이터 중복**
   
   - 동일 또는 유사 샘플이 여러 분할에 동시에 포함되서 실제보다 성능이 과대평가됨
   - 원인: 데이터 수집, 병합, 오버샘플링과 같은 서로 다른 데이터 소스들의 병합 시에 발생
   - 방지 방법: 분할 전/후 중복 검사, 오버샘플링은 분할 후 수행
   
   **4) 그룹 누수**
   
   - 서로 강하게 연관된 샘플들이 훈련·테스트에 나뉘어 들어가서, 테스트가 사실상 "거의 같은 데이터"가 되어버리는 현상
   - 즉 모델에게 **이 문제랑 거의 똑같은 문제를 훈련 때 이미 보여준 상황**을 만드는 것
   - 예: 동일 환자의 여러 CT, 연속 촬영된 객체 이미지
   - 데이터 생성 방식 이해 필요
   
   **5) 데이터 생성 과정에서 발생하는 누수**
   
   - 의료 절차, 장비, 프로세스 차이가 레이블을 암시함
   - 예: (앞의 의료 영상 사례) 암 의심 환자 → 더 좋은 CT 장비 → 이미지 차이 학습
   - 데이터 수집 및 처리 방식에 대한 이해 필수 + 정규화(평균, 분산 동일하게)로 어느 정도 해소 가능 + **전문가를 섭외하자**

#### 5.3.2 데이터 누수 검출 

| 방법 | 설명 |
| --- | --- |
| **상관 분석** | 피처-레이블 상관관계 비정상적으로 높으면 의심 |
| **Ablation Study(절제 연구)** | 피처 제거 시 성능 급락 여부 확인 |
| **신규 피처 감시** | 새 피처 추가 후 성능 급상승 시 누수 의심 |
| **테스트 데이터 관리** | 테스트 분할은 최종 평가에만 사용하도록 주의 (미리 사용 X) |

### 5.4 좋은 피처를 설계하는 방법 

- 일반적으로 피처를 추가하면 모델 성능은 향상되나, 많다고 해서 항상 좋아지진 않음 (필요충분조건은 아니다)
- 피처가 너무 많을 경우 다음과 같은 문제가 발생:

| 문제 | 영향 |
| --- | --- |
| 데이터 누수 위험 증가 | 성능 착시 발생 |
| 과적합 | 일반화 성능 저하 |
| 메모리, 필요 비용 증가 | 인프라 비용 상승 |
| 추론 레이턴시 증가 | 서비스 성능 저하 |
| 기술 부채 | 유지보수 난이도 상승 |

#### 5.4.1 피처 중요도 

- **피처 중요도의 정의**

   - 특정 피처를 제거했을 때 **모델 성능이 얼마나 감소하는지**로 측정
   - 예: XGBoost, SHAP, InterpretML 등 활용

- **SHAP의 장점**

   - 단순히 피처 중요도만 뽑아주는 게 아니라 모델의 특정 예측에 대한 피처 기여도 또한 측정해주기 때문에 특히 좋음

#### 5.4.2 피처 일반화 

- **피처 일반화의 정의**

   - 모델이 **본 적 없는 데이터(unseen data)** 에서도 피처가 동일하게 의미를 유지하는 능력
   - 일반화가 되지 않는 피처들도 있는데, 댓글 ID 같은 식별자는 고윳값이라서 일반화가 어려움

- **피처 평가 시 고려할 요소**

   1. **피처 커버리지**: 데이터 중 해당 피처 값이 존재하는 비율
      - 커버리지가 매우 낮으면 일반화 어려움
   
   2. **피처 값 분포**: 훈련 데이터에 나타난 값 범위와 테스트 데이터에 나타난 값 범위가 겹쳐야 함
      - 두 분포가 거의 겹치지 않으면 일반화 실패할 가능성이 높음
      - 다른 경우엔 데이터 분할 방식이나 데이터 누수를 의심해봐야 하는 경우에 해당

- **일반화와 구체성의 trade-off**

   - **HOUR_OF_THE_DAY(0~23)**: 정보가 풍부하지만 일반화 어려울 수 있음
     - 정보가 매우 풍부함
     - 오전 8시와 9시의 차이까지 모델이 알 수 있음
     - 하지만 데이터 분포가 조금만 바뀌어도 성능 흔들림
   
   - **IS_RUSH_HOUR(0, 1)**: 일반적이지만 시간에 대한 세부 정보 손실됨
     - "러시 아워인지 아닌지"만 제공
     - 정보는 줄어들지만
     - 시간 분포가 바뀌어도 안정적으로 작동
   
   → **결론**: 피처는 '정보를 얼마나 많이 주는가'와 '환경이 바뀌어도 의미를 유지하는가' 사이의 균형 게임

**Q1. 비무작위 결측과 무작위 결측의 차이점이 궁금합니다. 약간 지도, 비지도 사이의 준지도 느낌인가요?**

A1. 비무작위 결측(MNAR)과 무작위 결측(MAR)은 결측이 발생한 원인이 어디에 있는지에 따라 구분됩니다. MNAR은 결측값 자체(타겟 값)와 관련이 있고, MAR은 다른 관측된 변수와 관련이 있습니다. 지도/비지도 학습과는 직접적인 연관이 없고, 결측 메커니즘에 대한 분류입니다.

**Q2. 파생 변수는 단일, 피처 교차는 2개 이상인가?**

A2. 네, 맞습니다. 파생 변수는 하나의 피처를 변환해서 만든 것이고, 피처 교차는 2개 이상의 피처를 결합하여 새로운 피처를 만드는 것입니다.

**Q3. 댓글 id 같은 식별자는 피처 일반화에 도움이 되지 않지만 사용자 이름과 같이 댓글을 게시한 사용자 식별자는 모델 예측 수행 시 유용하다는 게 무슨 뜻인지 궁금합니다.**

A3. 그 ID가 '대상 자체'인지, 아니면 '대상의 행동 특성'을 대표하는지의 차이입니다. 댓글 ID는 "이 편지가 152번 봉투에 들어 있었음"을 말해주는 것이고, 사용자 이름(또는 사용자 ID)은 "이 편지를 쓴 사람은 항상 거짓말함" 같은 패턴을 학습할 수 있습니다. 즉, 사용자 ID는 그 사용자의 과거 행동 패턴(스팸 이력, 작성 스타일 등)을 대표하는 피처로 활용 가능하지만, 개별 댓글 ID는 단순히 고유 식별자일 뿐 일반화된 패턴을 제공하지 못합니다.

**Q4. 학습 가능한 위치 임베딩과 고정 위치 임베딩의 차이는?**

A4. 
- **학습 가능한 위치 임베딩 (BERT 방식)**: 위치 정보 자체도 학습을 통해 최적의 벡터값을 찾음. 데이터에 맞춰 유동적으로 최적화됨. 구현 시 위치마다 학습 가능한 파라미터 벡터 할당.
- **고정 위치 임베딩 (원본 Transformer 방식)**: 사인/코사인 함수로 미리 정의된 벡터 사용. 학습되지 않음. 장점은 훈련 데이터보다 긴 문장도 수학적 규칙으로 위치 추론 가능.
