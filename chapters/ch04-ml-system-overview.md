### 4.1 샘플링 (Sampling)

* **샘플링이 중요한 이유**: 전체 데이터 접근의 어려움, 처리 비용 및 시간 절감, 빠른 실험 가능
* **샘플링의 종류 및 특징**

| **분류** | **종류** | **특징 및 예시** |
| --- | --- | --- |
| **비확률 샘플링** | **편의, 눈덩이, 판단, 할당** | 확률이 아닌 기준/편의로 추출하여 대표성이 낮고 편향 위험이 큼<br><br>- **편의**: 구하기 쉬운 것만 추출(사내 직원 인터뷰)<br><br>- **눈덩이**: 기존 표본이 다음 표본을 소개(인스타 비공개 계정 팔로워 데이터 수집)<br><br>- **판단**: 전문가가 주관적으로 선택(연구원이 원하는 데이터 수집)<br><br>- **할당**: 그룹별 할당량만 맞추는 방식(연령대별 비율만 맞추고 무작위성 없음) |
| **단순 무작위** | Simple Random | 모든 샘플이 동일 확률로 선택됨. 구현은 쉬우나 희귀 클래스 누락 위험 존재 |
| **계층적 샘플링** | Stratified | 모집단을 그룹(계층, Stratum)으로 나누고 각 그룹에서 따로 샘플링하여 희귀 클래스 누락 방지 |
| **가중 샘플링** | Weighted | 샘플마다 가중치를 부여해 선택 확률 조절. 도메인 지식 반영 및 분포 보정에 활용 |
| **저수지 샘플링** | Reservoir | 스트리밍 환경에서 데이터 전체 크기를 몰라도 개를 동일 확률로 유지하는 알고리즘 |
| **중요도 샘플링** | Importance | 추출이 어려운 분포  대신 쉬운 분포 $Q(x)$에서 뽑고 가중치로 보정하는 기법 |

### 4.2 레이블링 (Labeling)

* **수작업 레이블링의 한계**: 높은 비용, 보안 문제, 느린 속도, 레이블 다중성(어노테이터 간 불일치)
* **자연 레이블 (Natural Labels)**: 시스템 운영 중 자연스럽게 생성되는 신호 (e.g., 추천 클릭, 실제 도착 시간)
  * **피드백 루프**: 예측 후 레이블을 얻기까지의 시간으로, 짧을수록 모델의 빠른 개선이 가능
  * **윈도 길이**: '클릭 안 함'을 음성 레이블로 판단하기까지의 대기 시간으로 정확도와 속도 간의 트레이드오프 발생


* **레이블 부족 문제 해결 전략**
  * **약한 지도 (Weak Supervision)**: 휴리스틱이나 규칙(LF)을 이용해 레이블 생성 (e.g., Snorkel)
  * **준지도 학습 (Semi-supervision)**: 소량의 레이블 데이터와 데이터 구조 가정을 통해 레이블 확장
  * **전이 학습 (Transfer Learning)**: 대형 사전 학습 모델을 가져와 제로샷이나 미세 조정 활용
  * **능동 학습 (Active Learning)**: 모델이 학습에 '가장 도움이 될 샘플'을 직접 선택해 레이블링 요청

### 4.3 클래스 불균형 문제 (Imbalanced Data)

* **개념**: 분류 태스크에서 훈련 데이터 내 클래스당 샘플 개수가 크게 차이나는 상태
* **회귀에서의 불균형**: 의료비 청구액처럼 Right-skewed된 분포에서 중앙값 근처보다 발생 빈도가 적은 고액 청구(95백분위수 등) 구간을 잘 예측하는 것이 비즈니스 손실 관리 측면에서 중요함
* **해결을 위한 3가지 접근법**

| **레벨** | **방법론** | **세부 내용** |
| --- | --- | --- |
| **Metric (지표)** | **적절한 지표 선택** | - Accuracy 대신 **F1 Score** 활용<br>- **ROC Curve**는 가짜 양성 비율(FPR)과 재현율(TPR)을 보지만 데이터 불균형이 심할 경우 성능 착시가 생길 수 있어 **PR Curve** 분석이 필수적임 |
| **Data (데이터)** | **분포 재조정** | - **Tomek 링크**: 반대 클래스 간 근접 샘플 쌍에서 다수 클래스 제거<br>- **SMOTE**: 소수 클래스 간 선분을 따라 가상 샘플 생성<br>- 단, 두 방법 모두 저차원 데이터에서만 효과적임 |
| **Algorithm** | **학습 방식 변경** | - **비용 민감 학습**: 오분류 비용 를 손실 함수에 반영 <br>- **클래스 균형 손실**: 샘플 수에 반비례하게 가중치 설정 <br>- **초점 손실 (Focal Loss)**: 틀리기 쉬운 샘플(Hard samples)에 가중치를 키워 집중 학습 |

  * 핵심 아이디어: 특정 클래스를 잘못 분류했을 때 발생하는 비용을 손실 함수에 직접 반영
  * <img width="400" height="224" alt="Image" src="https://github.com/user-attachments/assets/600b515a-06c2-45af-a432-ce2394d7b543" />

* **Algorithm2: 클래스 균형 손실 (Class-Balanced Loss)**
  * 핵심 아이디어: 각 클래스의 가중치를 해당 클래스의 샘플 수에 반비례하게 설정
  * 다수 클래스에 편향되는 현상을 막기 위해 소수 클래스를 잘못 예측했을 때 더 큰 불이익을 주는 방법
  
    ➡️ 일일이 비용 행렬을 정의하지 않아도 된다는 장점

* **Algorithm3: 초점 손실 (Focal loss)**
  * 핵심 아이디어: 예측이 맞을 확률이 낮을수록(틀릴 가능성이 높을수록) 샘플 가중치를 키워 손실 조정
  * 모델이 분류하기 쉬운 샘플보다 분류하기 어려운 샘플(Hard samples)에 집중하도록 인센티브를 주는 방식

### 4.4 데이터 증강 (Data Augmentation)

* **목적**: 훈련 데이터 수를 늘리고 모델이 노이즈 및 공격에 견고(Robust)해지도록 유도함
* **주요 유형**
  * **단순 레이블 보존 변환**: 이미지 자르기, 뒤집기, 회전 등. GPU가 훈련하는 동안 CPU에서 실시간 변환하므로 계산 비용이 매우 낮음. NLP에서는 동의어 교체나 유의어 검색 대체 활용
  * **교란 (Perturbation)**: 모델이 틀리도록 의도적으로 노이즈를 섞는 **Adversarial Attack** 기법. 픽셀 하나만 바꿔도 오분류가 발생하는 현상을 학습에 활용해 모델의 안정성 강화
  * **데이터 합성 (Synthesis)**: 개인정보 보호나 비용 문제 해결을 위해 가상 데이터를 생성하거나, NLP에서 템플릿을 사용하여 초기 모델을 부트스트랩함
