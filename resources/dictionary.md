# 단어집 📓
| **용어** | **정의** | **Chapter** |
| --- | --- | --- |
| **Throughput (처리량)** | 특정 기간 내에 처리된 쿼리 또는 요청의 수 (처리량) | Ch1 |
| **Latency (레이턴시)** | 요청이 시작된 후 응답이 돌아오기까지 걸리는 순수 처리 지연 시간 | Ch1 |
| **Response Time (응답 시간)** | 레이턴시에 네트워크 지연, 대기열 지연 등 기타 요소를 모두 포함한 최종 시간 | Ch1 |
| **Off-the-shelf (기성)** | 기성품이라는 뜻으로, 커스터마이징 없이 바로 사용 가능한 라이브러리/모델/솔루션 | Ch1 |
| **Ticket (고객 지원 티켓)** | 고객이 회사에 문의하거나 문제를 제기할 때 생성되는 문서/요청서 같은 것. 영화관 티켓처럼 번호표를 받는다는 의미에서 유래  | Ch1 |
| **Use Case (유스 케이스)** | 어떤 기술을 ‘어디에, 어떻게 쓰는지’를 나타내는 구체적인 사용 시나리오. ML 유스 케이스의 경우 머신러닝을 써서 해결하는 구체적인 문제/사용 시나리오를 뜻함 | Ch1 |
| **ROI (투자 대비 수익률)** | 투자 대비 수익률. ML 프로젝트의 성공을 측정하는 핵심 비즈니스 지표 | Ch2 |
| **Resource Scaling (자원 스케일링)** | 시스템에 필요한 컴퓨팅 자원(CPU, GPU 등)을 상황에 맞게 조절하는 것 | Ch2 |
| **Auto Scaling (오토 스케일링)** | 트래픽이나 부하에 따라 자원 스케일링을 자동으로 수행하는 기능 | Ch2 |
| **Artifact (아티팩트)** | ML 개발 과정에서 생성되는 부산물(학습된 모델 파일, 데이터 스냅샷, 로그 등) | Ch2 |
| **Data Engineering (데이터 엔지니어링)** | 데이터를 수집, 저장, 관리하고 ML 파이프라인으로 연결하는 인프라 작업 | Ch2 |
| **Feature Engineering (피처 엔지니어링)** | 모델이 학습하기 좋도록 도메인 지식을 활용해 데이터에서 '의미 있는 신호'를 추출/변환하는 과정 | Ch2 |
| **Silent Failure (조용히 실패)** | 시스템이 멈추지는 않지만, 잘못된 예측이나 동작을 에러 메시지 없이 계속 수행하는 상태 | Ch2 |
| **First Party Data (퍼스트 파티 데이터)** | 회사에서 사용자 또는 고객에 대해 이미 수집하고 있는 데이터 | Ch3 |
| **Second Party Data (세컨드 파티 데이터)** | 다른 회사에서 자체 고객에 대해 수집하는 데이터. 제공받으려면 비용을 지불해야 함 | Ch3 |
| **Third Party Data (서드 파티 데이터)** | 직접적인 고객이 아닌 공공 데이터를 수집한 것 | Ch3 |
| **Data Serialization (데이터 직렬화)** | 데이터 구조나 객체 상태를 저장 혹은 전송하고 나중에 재구성할 수 있는 포맷으로 변환하는 프로세스. 컴퓨터/네트워크로 전송하려면 데이터가 연속된 일련의 바이트 형태로 구성되어야 하기 때문에 필요한 처리 | Ch3 |
| **Text Blob (텍스트 블롭)** | DB나 파일에 문자열로 저장되는 비정형 또는 포맷이 지정되지 않은 텍스트 데이터 덩어리. 구조적이지 않아 처리나 분석하기 어려운 대량의 텍스트 데이터 | Ch3 |
| **Turing-complete (튜링 완전)** | SQL로 모든 계산 문제를 해결할 수 있다는 의미 (시간, 메모리 고려 없이) | Ch3 |
| **Schema-on-read (스키마-온-리드)** | 문서 DB에 데이터를 기록할 때는 스키마를 준수해야 하는 제약 조건이 없지만, 데이터를 읽는 애플리케이션은 스키마를 맞추기 위한 처리 작업이 필요함 | Ch3 |
| **Locality (지역성)** | 동일한 영역 내에서 관련 데이터를 저장하도록 하는 원칙 | Ch3 |
| **Bytestring (바이트스트링)** | 문자가 아니라 바이트(0-255 숫자)들의 나열로 이루어진 데이터 덩어리. 사람이 읽는 문자열이 아니라 컴퓨터가 다루는 원시 데이터 | Ch3 |
| **Opt-in (옵트인)** | 사용자가 명시적으로 동의해야만 데이터 수집이 가능한 방식 | Ch3 |
| **Storage Engine (스토리지 엔진)** | 데이터가 저장/조회/갱신되는 방식을 구현하는 시스템(또는 그 핵심 컴포넌트) | Ch3 |
| **Transaction (트랜잭션)** | OLTP 성격으로, 사용자 행동과 연결된 짧고 빈번한 쓰기/갱신 작업 중심의 처리를 요구(저지연/고가용성) | Ch3 |
| **Analytical Workload (분석)** | OLAP 성격으로, 대량 데이터 스캔·집계·다차원 조회 중심의 처리를 요구(열 지향/압축/집계 최적화 등) | Ch3 |
| **Pub-Sub (발행-구독 모델)** | 토픽에 이벤트를 발행하면 구독자가 이를 소비하는 패턴. 발행자는 메시지를 던지고, 구독자는 관심 있는 것만 받는 느슨한 연결 방식 | Ch3 |
| **Message Queue (메시지 큐)** | 메시지를 특정 소비자(또는 소비자 그룹)에 전달하는 패턴 | Ch3 |
| **Nearline (니어라인)** | 니어-온라인의 줄임말로, 데이터를 즉시 사용할 수는 없지만 사람의 개입 없이 빠르게 온라인으로 만들 수 있음을 의미.<br>자주 쓰진 않지만 필요할 때 바로 쓸 수 있는 데이터. (예: OLTP는 오늘의 거래 내역을, 니어라인은 최근 1-6개월 거래를, OLAP는 수년치 거래를 분석한 결과를 보여줌) | Ch4 |
| **Microservice Architecture (마이크로서비스 아키텍처)** | 애플리케이션을 별도의 서비스로 구조화 | Ch4 |
| **Retention Policy (리텐션 정책)** | 데이터를 얼마나 오래 저장할 것인가에 대한 규칙 | Ch4 |
| **Batch Processing (배치 처리)** | 데이터를 배치 작업에서 처리하는 것 | Ch4 |
| **Stream Processing (스트림 처리)** | 스트리밍 데이터에 대한 계산 | Ch4 |
| **Stateful Computation (상태 유지 계산)** | 이전 결과(상태)를 기억하면서 다음 데이터를 처리하는 계산. 즉, 과거 데이터를 기억하고 그 위에 누적해서 계산하는 방식 | Ch4 |
| **n-gram** | 주어진 텍스트 샘플 내 항목 n개의 연속 시퀀스. 가능한 조합을 n개의 단어를 이용해 다 만들어냄 | Ch5 |
| **피처 스케일링** | 모델에 피처를 입력하기 전에 각 피처를 유사한 범위로 스케일링하는 것 | Ch5 |
| **log transformation(로그 변환)** | 비대칭 분포를 따르는 피처들을 로그로 변환하여 데이터 왜곡을 줄이는 기법 | Ch5 |
| **이산화** | 연속형 피처를 불연속형 피처로 바꾸는 과정 | Ch5 |
| **cold start(콜드 스타트)** | 신규 범주가 추가될 때 모델이 해당 범주에 대한 학습 데이터가 없어 적절한 예측을 하지 못하는 현상 | Ch5 |
| **Hashing Trick(해싱 트릭)** | 해시 함수를 사용하여 범주형 데이터를 고정된 크기의 인덱스로 변환하는 기법. 신규 범주를 별도 처리 없이 즉시 인코딩 가능하게 함 | Ch5 |
| **Hash Collision(해시 충돌)** | 서로 다른 두 범주가 동일한 해시 인덱스를 배정받는 현상. 무작위로 발생하므로 특정 편향을 만들지 않음 | Ch5 |
| **Embedding(임베딩)** | 데이터를 기계가 이해할 수 있는 고정된 크기의 밀집 벡터로 변환한 것. 유사한 데이터는 임베딩 공간에서 가까이 위치 | Ch5 |
| **Fourier Features(푸리에 피처)** | 연속적인 좌표값을 사인/코사인 함수로 매핑하여 고차원 주파수 데이터로 변환한 것. 고주파수 디테일 학습에 효과적 | Ch5 |
| **AutoML (오토ML)** | ML을 사용해 문제에 가장 적합한 모델을 자동으로 선택하는 기법 | Ch6 |
| **Bootstrap(부트스트랩)** | 원본 데이터에서 복원 추출로 여러 개의 새로운 학습용 데이터셋을 만드는 방법. 여기서 각 데이터셋을 부트스트랩이라고 함 | Ch6 |
| **Perturbation Test (교란 테스트)** | 테스트 데이터에 의도적으로 잡음이나 변화를 주어 모델이 실제 환경의 불완전한 데이터에서도 잘 작동하는지 확인하는 테스트 | Ch6 |
| **Model Calibration (모델 보정)** | 모델이 출력한 확률이 실제 발생 빈도와 일치하도록 조정하는 것 | Ch6 |
| **Deploy (배포)** | 모델을 실행하고 액세스 가능하게 하는 것. 개발 환경에서 벗어나 스테이징 또는 프로덕션 환경으로 이동 | Ch7 |
| **Export (내보내기)** | 모델을 다른 애플리케이션에서 사용할 수 있는 형식으로 변환하는 일. 직렬화(Serialization)라고도 함 | Ch7 |
| **Software Rot / Bit Rot (소프트웨어 부패 / 비트 부패)** | 시간에 따라 소프트웨어 프로그램이 아무런 변화가 없어 보임에도 성능이 저하되는 현상 | Ch7 |
| **Data Distribution Shift (데이터 분포 시프트)** | 프로덕션에서 모델이 접하는 데이터 분포가 훈련된 데이터 분포와 다를 때 발생하는 문제 | Ch7 |
| **Online Prediction (온라인 예측)** | 예측에 대한 요청이 도착하는 즉시 예측이 생성되고 반환되는 경우. 온디맨드 예측, 동기 예측이라고도 함 | Ch7 |
| **Batch Prediction (배치 예측)** | 예측이 주기적으로 혹은 트리거될 때마다 생성되는 경우. 예측 결과를 저장하고 필요에 따라 검색. 비동기 예측이라고도 함 | Ch7 |
| **Inference (추론)** | 예측을 생성하는 과정 | Ch7 |
| **Batch Features (배치 피처)** | 데이터베이스나 데이터 웨어하우스의 데이터 같은 과거 데이터에서 계산된 피처 | Ch7 |
| **Streaming Features (스트리밍 피처)** | 스트리밍 데이터(실시간 전송 데이터)에서 계산된 피처 | Ch7 |
| **Online Features (온라인 피처)** | 온라인 예측에 사용되는 모든 피처. 메모리에 저장된 배치 피처도 포함 | Ch7 |
| **Streaming Prediction (스트리밍 예측)** | 스트리밍 피처를 사용하는 온라인 예측 | Ch7 |
| **Incremental Learning (증분 학습)** | 전체 모델을 처음부터 재훈련하지 않고 새로운 데이터로 기존 모델을 업데이트하는 학습 방식 | Ch7 |
| FPGA(Field Programmable Gate Array) | 회로를 나중에 바꿀 수 있는 칩. 레고 블록 같은 개념으로 조립했다가 다시 부수고 다른 모양으로 조립이 가능한 칩 | Ch7 |
| ASIC(Application-Specific Integrated Circuit) | 특정 목적용으로 회로를 아예 고정해서 만든 칩. 시멘트 건물처럼 처음 설계하면 절대 바꿀 수 없는 칩. 대신 튼튼하고 효율이 좋은 편임 | Ch7 |
| Hardware Backend(하드웨어 백엔드) | ML 프레임워크의 연산을 특정 하드웨어 구조에 맞게 매핑하여 실제 실행을 담당하는 계층 | Ch7 |
| Intermediate Representation(중간 표현) | 모델/프로그램을 하드웨어에 독립적인 ‘중간 형태’로 표현한 것. ML 프레임워크와 하드웨어 백엔드 사이에서 모델을 공통된 형태로 표현하는 중간 표현 | Ch7 |
| Lowering(로어링) | 고수준의 프레임워크 코드를 저수준의 하드웨어 네이티브 코드로 ‘낮춘다’는 의미의 프로세스를 일컫음 | Ch7 |
| WASM(WebAssembly) | 다양한 언어로 작성된 프로그램을 웹 브라우저상에서 모델을 빌드하고 특정 하드웨어에서 실행되록 해주는 개방형 표준 | Ch7 |
