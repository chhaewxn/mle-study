# 단어집 📓
| **용어** | **정의** | **Chapter** |
| --- | --- | --- |
| **Throughput (처리량)** | 특정 기간 내에 처리된 쿼리 또는 요청의 수 (처리량) | Ch1 |
| **Latency (레이턴시)** | 요청이 시작된 후 응답이 돌아오기까지 걸리는 순수 처리 지연 시간 | Ch1 |
| **Response Time (응답 시간)** | 레이턴시에 네트워크 지연, 대기열 지연 등 기타 요소를 모두 포함한 최종 시간 | Ch1 |
| **Off-the-shelf (기성)** | 기성품이라는 뜻으로, 커스터마이징 없이 바로 사용 가능한 라이브러리/모델/솔루션 | Ch1 |
| **Ticket (고객 지원 티켓)** | 고객이 회사에 문의하거나 문제를 제기할 때 생성되는 문서/요청서 같은 것. 영화관 티켓처럼 번호표를 받는다는 의미에서 유래  | Ch1 |
| **Use Case (유스 케이스)** | 어떤 기술을 ‘어디에, 어떻게 쓰는지’를 나타내는 구체적인 사용 시나리오. ML 유스 케이스의 경우 머신러닝을 써서 해결하는 구체적인 문제/사용 시나리오를 뜻함 | Ch1 |
| **ROI (투자 대비 수익률)** | 투자 대비 수익률. ML 프로젝트의 성공을 측정하는 핵심 비즈니스 지표 | Ch2 |
| **Resource Scaling (자원 스케일링)** | 시스템에 필요한 컴퓨팅 자원(CPU, GPU 등)을 상황에 맞게 조절하는 것 | Ch2 |
| **Auto Scaling (오토 스케일링)** | 트래픽이나 부하에 따라 자원 스케일링을 자동으로 수행하는 기능 | Ch2 |
| **Artifact (아티팩트)** | ML 개발 과정에서 생성되는 부산물(학습된 모델 파일, 데이터 스냅샷, 로그 등) | Ch2 |
| **Data Engineering (데이터 엔지니어링)** | 데이터를 수집, 저장, 관리하고 ML 파이프라인으로 연결하는 인프라 작업 | Ch2 |
| **Feature Engineering (피처 엔지니어링)** | 모델이 학습하기 좋도록 도메인 지식을 활용해 데이터에서 '의미 있는 신호'를 추출/변환하는 과정 | Ch2 |
| **Silent Failure (조용히 실패)** | 시스템이 멈추지는 않지만, 잘못된 예측이나 동작을 에러 메시지 없이 계속 수행하는 상태 | Ch2 |
| **First Party Data (퍼스트 파티 데이터)** | 회사에서 사용자 또는 고객에 대해 이미 수집하고 있는 데이터 | Ch3 |
| **Second Party Data (세컨드 파티 데이터)** | 다른 회사에서 자체 고객에 대해 수집하는 데이터. 제공받으려면 비용을 지불해야 함 | Ch3 |
| **Third Party Data (서드 파티 데이터)** | 직접적인 고객이 아닌 공공 데이터를 수집한 것 | Ch3 |
| **Data Serialization (데이터 직렬화)** | 데이터 구조나 객체 상태를 저장 혹은 전송하고 나중에 재구성할 수 있는 포맷으로 변환하는 프로세스. 컴퓨터/네트워크로 전송하려면 데이터가 연속된 일련의 바이트 형태로 구성되어야 하기 때문에 필요한 처리 | Ch3 |
| **Text Blob (텍스트 블롭)** | DB나 파일에 문자열로 저장되는 비정형 또는 포맷이 지정되지 않은 텍스트 데이터 덩어리. 구조적이지 않아 처리나 분석하기 어려운 대량의 텍스트 데이터 | Ch3 |
| **Turing-complete (튜링 완전)** | SQL로 모든 계산 문제를 해결할 수 있다는 의미 (시간, 메모리 고려 없이) | Ch3 |
| **Schema-on-read (스키마-온-리드)** | 문서 DB에 데이터를 기록할 때는 스키마를 준수해야 하는 제약 조건이 없지만, 데이터를 읽는 애플리케이션은 스키마를 맞추기 위한 처리 작업이 필요함 | Ch3 |
| **Locality (지역성)** | 동일한 영역 내에서 관련 데이터를 저장하도록 하는 원칙 | Ch3 |
| **Bytestring (바이트스트링)** | 문자가 아니라 바이트(0-255 숫자)들의 나열로 이루어진 데이터 덩어리. 사람이 읽는 문자열이 아니라 컴퓨터가 다루는 원시 데이터 | Ch3 |
| **Opt-in (옵트인)** | 사용자가 명시적으로 동의해야만 데이터 수집이 가능한 방식 | Ch3 |
| **Nearline (니어라인)** | 니어-온라인의 줄임말로, 데이터를 즉시 사용할 수는 없지만 사람의 개입 없이 빠르게 온라인으로 만들 수 있음을 의미.<br>자주 쓰진 않지만 필요할 때 바로 쓸 수 있는 데이터. (예: OLTP는 오늘의 거래 내역을, 니어라인은 최근 1-6개월 거래를, OLAP는 수년치 거래를 분석한 결과를 보여줌) | Ch4 |
| **Microservice Architecture (마이크로서비스 아키텍처)** | 애플리케이션을 별도의 서비스로 구조화 | Ch4 |
| **Retention Policy (리텐션 정책)** | 데이터를 얼마나 오래 저장할 것인가에 대한 규칙 | Ch4 |
| **Batch Processing (배치 처리)** | 데이터를 배치 작업에서 처리하는 것 | Ch4 |
| **Stream Processing (스트림 처리)** | 스트리밍 데이터에 대한 계산 | Ch4 |
| **Stateful Computation (상태 유지 계산)** | 이전 결과(상태)를 기억하면서 다음 데이터를 처리하는 계산. 즉, 과거 데이터를 기억하고 그 위에 누적해서 계산하는 방식 | Ch4 |
